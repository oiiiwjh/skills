# GitHub提交管理技能

## 概述

此技能提供完整的GitHub仓库提交工作流程，包括仓库状态检查、远程链接验证、代码审核和提交创建。确保代码正确提交到指定的GitHub仓库。

## 工作流程

### 1. 检查当前仓库状态
首先检查当前目录是否是Git仓库，以及是否已配置远程仓库链接。

**触发条件**：当用户需要提交代码但不确定当前仓库状态时。

**操作步骤**：
1. 运行 `scripts/check_git_status.py` 检查仓库状态
2. 显示远程仓库链接、当前分支和未提交的更改
3. 确认是否使用现有的远程仓库链接

**示例用户请求**：
- "检查当前仓库状态"
- "查看Git仓库的远程链接"
- "确认当前分支和更改状态"

### 2. 验证或更新远程仓库链接
如果远程仓库链接不存在或需要更新，允许用户验证或更新GitHub仓库链接。

**触发条件**：
- 当前仓库没有配置远程链接
- 用户需要更改远程仓库链接
- 远程链接无效或需要验证

**操作步骤**：
1. 使用 `scripts/update_remote.py` 验证GitHub URL格式
2. 如果远程已存在，提示用户确认是否更新
3. 添加或更新远程仓库链接
4. 测试远程连接

**示例用户请求**：
- "更新远程仓库链接到 https://github.com/username/repo.git"
- "添加GitHub远程仓库"
- "验证当前远程链接是否正确"

### 3. 审核代码并创建提交
审核代码更改，生成合适的提交消息，并创建提交。

**触发条件**：当用户需要提交代码更改时。

**操作步骤**：
1. 使用 `scripts/create_commit.py` 检查代码更改
2. 根据更改类型生成提交消息建议
3. 验证提交消息格式
4. 添加更改到暂存区并创建提交
5. 可选：推送到远程仓库

**示例用户请求**：
- "提交当前更改"
- "创建提交并推送到GitHub"
- "审核代码并生成提交"

## 脚本使用说明

### check_git_status.py
检查Git仓库状态的脚本。

**用法**：
```bash
python scripts/check_git_status.py [目录路径]
```

**输出**：
- 仓库状态（是否是Git仓库）
- 远程仓库链接
- 当前分支
- 未提交的更改列表
- 最近提交历史

### update_remote.py
更新Git远程仓库链接的脚本。

**用法**：
```bash
python scripts/update_remote.py <目录> <远程名称> <GitHub URL>
```

**示例**：
```bash
python scripts/update_remote.py . origin https://github.com/username/repo.git
```

**功能**：
- 验证GitHub URL格式
- 添加或更新远程仓库
- 测试远程连接

### create_commit.py
创建Git提交的脚本。

**用法**：
```bash
python scripts/create_commit.py <目录> <提交消息> [--push]
```

**示例**：
```bash
# 仅创建提交
python scripts/create_commit.py . "修复登录页面样式问题"

# 创建提交并推送
python scripts/create_commit.py . "添加新功能模块" --push
```

**功能**：
- 验证提交消息格式
- 自动生成提交消息建议
- 添加所有更改到暂存区
- 创建提交
- 可选推送到远程仓库

## 完整工作流程示例

### 场景1：新仓库首次提交
1. 用户： "我需要提交代码到GitHub仓库 https://github.com/myuser/myproject.git"
2. 检查当前仓库状态
3. 发现没有远程链接，提示用户确认
4. 添加远程仓库链接
5. 审核代码更改
6. 生成提交消息并创建提交
7. 推送到远程仓库

### 场景2：更新现有仓库
1. 用户： "提交我的更改"
2. 检查当前仓库状态，显示现有远程链接
3. 确认使用现有远程链接
4. 审核代码更改
5. 生成提交消息并创建提交
6. 推送到远程仓库

### 场景3：更改远程仓库
1. 用户： "我想更改远程仓库到新的GitHub地址"
2. 检查当前远程链接
3. 提示用户确认更新
4. 更新远程仓库链接
5. 测试连接
6. 继续提交流程

## 最佳实践

### 提交消息规范
- 使用中文或英文描述更改内容
- 消息长度：10-200字符
- 清晰描述更改的目的
- 避免使用模糊的词语如"更新"、"修复"

### 远程链接验证
- 确保GitHub URL格式正确
- 测试远程连接是否正常
- 确认有访问权限

### 代码审核
- 检查更改的文件列表
- 确认没有意外更改
- 确保不提交敏感信息（如API密钥、密码）

## 错误处理

### 常见错误及解决方案
1. **不是Git仓库**：在当前目录初始化Git仓库
2. **远程链接无效**：检查URL格式和网络连接
3. **提交消息太短**：提供更详细的描述
4. **没有更改可提交**：确认有未提交的更改
5. **推送权限不足**：检查GitHub访问权限

### 安全注意事项
- 不自动提交包含敏感信息的文件
- 提示用户确认远程仓库链接
- 不自动强制推送更改
